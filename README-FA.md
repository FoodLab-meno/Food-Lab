# منوی دیجیتال FoodLab

نسخه بازطراحی‌شده با الهام از تصویر مرجع FoodLab: سربرگ برند، بنر سبز، کارت‌های تصویری دسته‌بندی، تیتر نارنجی و کارت‌های محصول. صفحه عمومی هیچ دکمه یا پیوندی به مدیریت ندارد.

## فایل‌ها
- `index.html`: منوی عمومی مشتریان
- `style.css`: طراحی واکنش‌گرا و پنل مدیر
- `menu.js`: نمایش محصولات و قیمت‌ها
- `admin.html`: ورود مدیر؛ از منوی عمومی لینک نشده است
- `admin.js`: ورود و ذخیره قیمت‌ها با Supabase Auth
- `config.js`: تنظیمات عمومی اتصال Supabase
- `supabase-setup.sql`: ساخت جدول و سیاست‌های امنیتی
- `assets/`: تصاویر برش‌خورده از طرح مرجع

## راه‌اندازی امن مدیریت قیمت
1. در Supabase یک پروژه بساز.
2. از Authentication > Users فقط یک کاربر برای خودت بساز. ثبت‌نام عمومی را غیرفعال کن.
3. شناسه UUID کاربر مدیر را از همان صفحه کپی کن.
4. در فایل `supabase-setup.sql` هر سه مورد `PASTE_ADMIN_USER_ID_HERE` را با UUID مدیر جایگزین کن و سپس SQL را در SQL Editor اجرا کن. اگر قبلاً SQL قدیمی اجرا شده، این نسخه را اجرا کن تا سیاست‌های قدیمی حذف شوند.
5. از Project Settings > API، Project URL و کلید عمومی anon/publishable را بردار.
6. در `config.js` مقدارهای `SUPABASE_URL` و `SUPABASE_ANON_KEY` را وارد کن و `ADMIN_USER_ID` را هم با همان UUID مدیر جایگزین کن.
7. هرگز `service_role` key را در این فایل قرار نده.
8. در GitHub Pages فایل‌ها را از ریشه مخزن یا `/docs` منتشر کن. اگر پروژه در زیرپوشه‌ای به نام `foodlab` است، محتوای داخل آن را به ریشه مخزن منتقل کن؛ GitHub Pages در حالت Deploy from a branch پوشه دلخواه `/foodlab` را به‌عنوان منبع انتخاب نمی‌کند.

## آدرس مدیریت
پس از انتشار، صفحه ورود مدیر در مسیر `admin.html` قرار دارد؛ از صفحه عمومی هیچ لینکی به آن وجود ندارد. پنهان‌کردن لینک، به‌تنهایی امنیت نیست: امنیت واقعی با ورود Supabase و سیاست‌های RLS برقرار می‌شود و فقط UUID حساب مدیر اجازه دیدن همه محصولات و تغییر قیمت‌ها را دارد.

## یادآوری
قیمت‌ها عمداً خالی هستند تا مدیر آن‌ها را وارد کند. نام محصولات اولیه نمونه‌اند و پیش از انتشار نهایی باید با منوی واقعی تطبیق داده شوند.
